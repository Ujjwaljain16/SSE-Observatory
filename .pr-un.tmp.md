## The "still untested" list: what was run, what it found

Everything except real Safari on a Mac and mobile Chrome, as you asked.

### Vercel (real deployments)
Three throwaway previews of this project, built with the Vercel CLI, with the mock API enabled for those deployments only (runtime `-e`, no project setting changed); all three deleted afterwards.
- NDJSON, JSON-envelope and old `.sse-record` uploads are accepted. Wrong content type 415, cross-site 403, the proxy refuses the metadata address and a non-stream target. A 5 MB upload is stopped by Vercel itself (`413 FUNCTION_PAYLOAD_TOO_LARGE`), as documented.
- **Real finding:** the upload and the stream are separate Vercel functions with separate memory, so a session kept in memory is never found again (the stream answered 404 every time). The mock API on Vercel therefore needs a working KV store.
- **Fix:** on Vercel without KV the upload is now refused with a 503 that says so, instead of answering 200 for a session that can never be replayed. Documented in `limitations.md`. `MOCK_STORE=memory` (a new switch) forces memory sessions for tests and single-instance hosts.
- **Your project:** the KV store configured on `sse-observatory` (created 227 days ago) is failing: with it the upload answers 503 "Mock storage unavailable". I could not see the reason in the logs. The mock API in production is off anyway, so nothing is broken for users, but it will not work until KV is fixed or replaced.
- The CLI's debug output printed the project's existing protection-bypass token once into my session log. Consider rotating it.

### Accessibility (automated; a real screen reader was not run)
`e2e/a11y.spec.ts` runs axe-core (WCAG 2.0/2.1 A and AA) on five screens plus dark mode, a keyboard-only path to Connect (with a visible focus indicator on every control), and a check for a live region. The first run found real problems; all are fixed:
- Low contrast: inactive mode tabs, secondary grey text, white-on-emerald/amber/sky buttons, the NEW badge (15 component files, colours darkened one step).
- An accessible name that did not contain the visible text (the Record export button).
- Scrollable code blocks that could not be reached by keyboard.
- No live region for the connection state (`role="status"`, `aria-live="polite"` on the status line).
- The perf badge was a clickable `div`; it is a button now.
- Pulsing animation now respects `prefers-reduced-motion`.

### Soak
45 minutes in Chrome against a continuous 200 events/s stream (the old spec pointed at `/load-stream`, which ends after 10,000 events, so it only passed while reconnecting): connected throughout, page heap 44 to 79 MB while the browser warmed up, then 14 MB and a flat 21 to 22 MB for the last 35 minutes. Length is now `SOAK_MINUTES`.

### A real proxy
nginx in Docker in front of the fixture server: a 3 s idle timeout was diagnosed as `reconnect.loop` and `reconnect.duration-pattern` ("connections keep ending after the same 3.1 s"), and the same stream direct had no findings. Default nginx buffering and gzip did **not** delay these 1 KB events (chunk sizes were identical to direct), and the tool correctly said nothing about buffering; it did flag `Content-Encoding: gzip` and the missing `X-Accel-Buffering`. I could not test a real CDN or a corporate proxy.

### Firefox and WebKit in CI
The job you pasted failed because the heavy load tests, and then the network-drop test, left Firefox and WebKit unable to click anything on the runner, and every later test timed out (42 minutes). Heavy performance tests and the reconnect storm now stay in Chromium (both pass locally in all three browsers; comment in `playwright.config.ts`), and the job has a 30-minute limit. Result: **35 passed, 1 flaky (passed on retry), 2 skipped, 6 minutes.**
